# План: Fitness Dashboard (особистий PWA для iPhone)

Робочий план проєкту. Оновлюю чекбокси в міру виконання.

## 1. Ціль

Особистий безкоштовний застосунок на iPhone, який:

- фотографує чек InBody, сам розпізнає цифри (OCR) і зберігає замір;
- показує склад тіла і прогрес на графіках (вага → ціль 83 кг, м'язи, жир, сегменти рук і ніг);
- веде журнал тренувань із шаблонами full-body і рахує прогрес сили (e1RM);
- показує баланс навантаження по групах м'язів за тиждень;
- має дизайн у стилі iOS Liquid Glass.

## 2. Рішення, погоджені з власником

- Мова інтерфейсу: **українська**.
- Тема: **світла і темна**, перемикач у налаштуваннях: Системна / Світла / Темна (за замовчуванням системна).
- Тренування записуються **по кожному підходу окремо** (вага, повтори) з таймером відпочинку, як у Strong/Hevy.
- Шаблони full-body A/B/C пропоную я, власник затверджує (затверджені, таблиця в розділі 8).
- OCR чека: **автоматично**, з екраном підтвердження.

## 3. Обмеження та рішення

| Вимога | Рішення |
|---|---|
| iPhone, без Mac і без $99/рік | **PWA**: встановлюється з Safari через «На початковий екран» |
| Безкоштовно | Хостинг **GitHub Pages** (репозиторій публічний: у ньому тільки код, без моїх даних) |
| Дані локально | **IndexedDB** на телефоні (через Dexie); жодного бекенду |
| Без Docker / серверів | Статична збірка Vite, деплой через GitHub Actions |
| Фото чека → цифри | **Tesseract.js** прямо в браузері, офлайн, без платних API |
| Бекап | Експорт/імпорт усіх даних у JSON-файл (Files / iCloud Drive) |

## 4. Стек

- **Vite + React + TypeScript**
- **vite-plugin-pwa**: manifest, service worker, офлайн-кеш (разом із моделлю Tesseract `eng.traineddata`)
- **Dexie.js**: IndexedDB з типами і міграціями схеми
- **Tesseract.js v5**: OCR, worker і мовні дані віддаються з нашого ж домену, щоб усе працювало офлайн
- **Chart.js + react-chartjs-2**: графіки (лінії, стовпці, радар для балансу м'язів)
- **React Router** (HashRouter, бо GitHub Pages не вміє SPA-rewrites)
- **Vitest**: юніт-тести парсера OCR і розрахунків
- Шрифт: системний `-apple-system` / SF Pro (на iPhone виглядає нативно)

## 5. Дизайн: Liquid Glass

**Важливо:** популярні бібліотеки (`liquid-glass-react` та схожі) дають заломлення через SVG-фільтр `feDisplacementMap` у `backdrop-filter`. У Safari (WebKit) це **не рендериться**, а всі браузери на iPhone працюють на WebKit. Тому PWA на iPhone цю частину ефекту не покаже.

Рішення: власний компонент `<Glass>` на CSS, який у Safari виглядає максимально близько до iOS 26:

- `backdrop-filter: blur(24px) saturate(180%)` (+ `-webkit-` префікс);
- напівпрозорий фон `rgba(255,255,255,0.12)` (світла тема) / `rgba(30,30,35,0.35)` (темна);
- «скляний» край: `border: 1px solid rgba(255,255,255,0.35)` + внутрішні `box-shadow` (світлий зверху, темніший знизу);
- спекулярний відблиск: псевдоелемент `::before` з radial/linear-gradient, який трохи рухається за пальцем або нахилом (DeviceOrientation, з дозволу);
- м'яка тінь під панеллю;
- живий фон: кілька розмитих кольорових «плям», що повільно рухаються, щоб скло було що розмивати;
- пружні анімації натискання (`transform: scale(0.97)` + spring easing);
- `prefers-reduced-motion` вимикає рух;
- **прогресивне покращення:** якщо браузер підтримує SVG-фільтри в `backdrop-filter` (Chrome на ПК), додається справжнє заломлення по краях. На iPhone працює CSS-версія.

Компоненти: `Glass` (панель/картка), `GlassButton`, `GlassTabBar` (плаваюча нижня навігація як в iOS 26), `GlassSheet` (bottom sheet для форм), `GlassSegmented`.

## 6. Модель даних (Dexie)

```ts
inbodyScans: { id, date, weight, muscle /*SMM*/, fatKg, pbf, tbw, ffm, bmi, whr, visceral, bmr, fitnessScore,
               lean: {ra, la, tr, rl, ll}, fat: {ra, la, tr, rl, ll}, photoId?, ocrConfidence?, createdAt }
weighIns:    { id, date, weight }
photos:      { id, blob, createdAt }                       // фото чеків
exercises:   { id, name, primary: MuscleGroup[], secondary: MuscleGroup[], archived }
templates:   { id, name /*Full body A*/, items: { exerciseId, targetSets, repRange }[] }
workouts:    { id, date, templateId?, note? }
sets:        { id, workoutId, exerciseId, setIndex, weight, reps, done, pain?: boolean, completedAt }
settings:    { goalWeight: 83, weeklySetTarget: {min, max}, theme: 'system' | 'light' | 'dark', restSeconds }
```

`MuscleGroup`: chest, back, shoulders, biceps, triceps, quads, hamstrings, glutes, calves, core.

## 7. OCR чека InBody 170

Пайплайн:

1. `<input type="file" accept="image/*" capture="environment">` → фото з камери.
2. Препроцесинг на `<canvas>`: обрізка, grayscale, підсилення контрасту, адаптивний поріг (термопапір блідий), збільшення до ~2000 px по висоті.
3. Tesseract (`eng`, PSM 6) → текст по рядках.
4. **Парсер** (чиста функція, покрита тестами): шукає мітки й числа після них:
   `Weight`, `Muscle`, `Fat`, `TBW`, `FFM`, `BMI`, `PBF`, `WHR`, `Visceral Fat`, `BMR`, блоки `Segmental Lean` / `Segmental Fat` (Right Arm, Left Arm, Trunk, Right Leg, Left Leg), `Fitness Score`, дата з шапки (`MM/DD/YY HH:MM`).
   - Типові помилки OCR: `O→0`, `l/I→1`, `S→5`, кома замість крапки, пропущена крапка (`774` → `77.4` за діапазоном).
   - Перевірки на здоровий глузд: `muscle + fat ≈ weight`, `pbf ≈ fat/weight·100`, `ffm ≈ weight − fat`, сума сегментів ≈ ffm. Поле, що не проходить, підсвічується.
5. Екран підтвердження: усі поля заповнені, сумнівні підсвічені, поруч мініатюра фото. Я правлю і зберігаю.

Тестова фікстура: текст, який Tesseract видає з мого фото чека від 01.11.2026. Саме фото лежить у `fixtures/private/` і **не комітиться** (є в `.gitignore`).

## 8. Екрани

Нижня скляна таб-панель (усі тексти українською):

1. **Огляд**: вага і прогрес до 83 кг, картки складу тіла зі зміною від попереднього заміру, міні-графік ваги, «цього тижня: N тренувань, M підходів».
2. **Тренування**: старт із шаблону (Full body A/B/C) або порожнє; кожен підхід окремим рядком (вага, повтори, галочка «виконано»); підказка з минулого разу; таймер відпочинку стартує після галочки; позначка «болить».
3. **Заміри**: кнопка «Сфотографувати чек» → OCR → підтвердження; швидке зважування; історія замірів із фото.
4. **Прогрес**: графіки ваги, м'язів і жиру; сегменти рук і ніг між замірами; e1RM по кожній вправі; тижневий об'єм; **баланс по групах м'язів**.
5. **Налаштування**: ціль ваги, редактор вправ і шаблонів, тема (Системна / Світла / Темна), час відпочинку, експорт/імпорт JSON.

### Баланс по групах м'язів

- Підходи за тиждень на кожну групу: основна група +1, допоміжна +0.5.
- Діаграма-радар і стовпці з цільовою смугою (за замовчуванням 10–20 підходів на тиждень, змінюється в налаштуваннях).
- Підсвічує групи, що відстають, і показує тренд за 4 тижні.

### Шаблон full-body

- 3 шаблони (A/B/C) по 5–6 вправ, 3 тренування на тиждень.
- **Без** присідань, румунської тяги, випадів і горизонтальних тяг (болять поперек і коліна). Ноги: жим ногами, розгинання й згинання ніг, носки.
- Склад шаблонів пропоную я, затверджує власник; редагуються в застосунку.

**Затверджено власником:**

| | A | B | C |
|---|---|---|---|
| 1 | Жим лежачи | Жим гантелей на похилій лаві | Жим гантелей над головою сидячи |
| 2 | Тяга верхнього блока широким хватом | Підтягування (або в гравітроні) | Тяга верхнього блока вузьким хватом |
| 3 | Жим ногами | Розгинання ніг | Жим ногами (вузька постановка) |
| 4 | Згинання ніг сидячи | Підйом на носки стоячи | Згинання ніг лежачи |
| 5 | Згинання на біцепс зі штангою | Махи гантелями в сторони | Віджимання на брусах |
| 6 | Розгинання на трицепс на блоці | Молотки | Зворотні розведення в тренажері (задня дельта) |

По 3 робочі підходи, 6–12 повторів на базових, 10–15 на ізолюючих.

## 10. Ризики

- **OCR на термочеку** може помилятися → завжди є екран підтвердження + перевірки сум; фото краще робити рівно і при хорошому світлі.
- **Сховище Safari**: застосунок, встановлений на початковий екран, не підпадає під 7-денне очищення даних, але при видаленні іконки дані зникають → регулярний експорт JSON (нагадування раз на місяць).
- **Продуктивність** `backdrop-filter` на багатьох панелях одночасно → обмежити кількість скляних шарів на екрані, на графіках використовувати звичайний фон.
- **Розмір Tesseract** (~10 МБ разом із мовою) → вантажиться один раз і кешується service worker'ом.
